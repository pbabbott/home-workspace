# CLAUDE.md patterns (distilled from the home-* repos)

Live examples to copy from: `home-kubernetes/CLAUDE.md`, `home-playbooks/CLAUDE.md` (root);
`home-kubernetes/scripts/CLAUDE.md`, `home-playbooks/scripts/CLAUDE.md`, `home-web-apps/scripts/CLAUDE.md` (manifest);
`home-playbooks/terraform/CLAUDE.md` (layout + hard rules); `home-web-apps/packages/{source-access,homelab-db}/CLAUDE.md`
and `apps/backup-worker/CLAUDE.md` (invariants); `home-web-apps/packages/fui-components/CLAUDE.md` (explicit strict conventions).

## Checklist (root file)

- [ ] `# <repo>` + 1-2 line purpose + pointer to `README.md` ("Start here" / full inventory).
- [ ] **Layout** table (`Path | Purpose`); each row says where the index/manifest for that area lives.
- [ ] **Domain facts inline**: the names someone would say in a prompt (hosts, workloads, clusters, scripts) with
      their role here. By-name lists for minor items; own bullet + 1-2 sentences for load-bearing ones.
- [ ] **How things fit together**: the 5-8 infra roles that explain this homelab (ingress, DNS, secrets, storage...),
      each pointing at its reference doc.
- [ ] **Scripts** section: "Prefer these over hand-rolled commands (details + manifest: `scripts/CLAUDE.md`, keep it
      updated)", 3-4 workflow bullets, caveats (`source` vs run, destructive scripts).
- [ ] **Agents and skills** (`.claude/agents`, `.claude/skills`, and cross-repo ones like `dns-expert`), one line each.
- [ ] **Documentation map**: one bullet per docs folder saying when to use it; "read before X" docs in bold.
- [ ] **Rules of the road**: short imperative list; each rule one line + pointer to the guide holding the detail.
- [ ] History fenced off in one bullet or a footnote.
- [ ] ~100 lines; every path/command exists; no generic tool explanations; no "Be brief"-style meta text.

## Pointer format

Good: `` `docs/ai-reference/gen3-data-move.md` — **read before moving an app's data gen2 -> gen3**: Longhorn restore, PVC rules, rollback ``
Bad: pasting the five restore steps into CLAUDE.md. Bad: "see the docs" with no path or summary.

## Nested templates

- **Manifest** (`scripts/`): intro (how to run, prerequisites, source-vs-run) -> `## Manifest` table
  (`Script | Use (run / source / pre-commit) | What it does`, exactly one row per file, enforced by a hook) ->
  `## Common workflows` -> `## Keeping this current` (same-commit rules; one script per job; no back-compat wrappers).
- **Layout + hard rules** (`terraform/`): where each root lives, how to run it, state/credential preconditions, and the
  "do NOT" rules (e.g. no DNS records in Terraform).
- **Invariants** (package/app): pointer to README/docs; the rules any change must keep; "keep X in sync with Y";
  how to build/test (and stale-build gotchas).
- **Strict conventions** (`fui-components`): explicit rules are fine when the directory needs them; keep to what a
  reviewer would enforce.
